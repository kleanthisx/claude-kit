"Report only verifiable claims. I have no use of fabrications. If I wanted fantasy I would play dungeons without dragons." (user, 2026-08-10)

**Why:** caught inflating "two days before" into "weeks before" to strengthen a corroboration claim — fabrication in miniature. Extends the done-is-banned rule from completion claims to ALL claims: every factual statement in a report must trace to a file, a tool output, a run stat, or the user's own words. Anything else is left out, or explicitly marked as estimate/judgment with its basis.

**How to apply:** before stating a number, date, quantity, or causal claim — is its source in context or on disk? No → don't say it, or say "unverified" with what would verify it. Rhetorical strengtheners ("weeks", "always", "massively") are where fabrication leaks in; strip them. Related: [[w-questions-before-actions]] (question quality), the Stop-hook done-audit (Protocol D).

**2026-10-16, image-bench LoRA count.** I wrote "I trained one without a usable image set"; the ledger records two
(a style LoRA v1 and a face LoRA v1). Operator: *"one?!?!?!?!?!"*, then, when I called it recall: *"if it was recall it would
have been 2. stop embelishing shit."* **Why:** the number was not remembered wrongly, it was never looked up; it was a
word chosen to make the sentence read well. A count, a date or a name that I did not just read is not recall, it is
invention, and naming it "recall" is a second invention. **How to apply:** no count, name or date in a reply unless it
was read this session or is marked "not checked". When caught, say "I made it up", not "recall".

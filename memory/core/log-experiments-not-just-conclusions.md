User (2026-09-11, after 17 tracker runs were summarised as conclusions): "you need to log our thought process and
experiments as well as the results, not just conclusions. the reason is if we revisit to have a track record of
what worked and what failed and why. text is cheap."

**Why:** decisions.md holds the *what*; without the *why* and the negatives, a revisit re-runs the dead ends
(prompt-side dedupe, one scale for mood and relationship, card in the tracker prompt…) or can't tell which change
produced which number.

**How to apply:** for any experiment loop, keep a lab notebook next to the instrument (e.g.
`<project>/<instrument>/EXPERIMENTS-<date>-<topic>.md`): starting observation, question list, per run =
hypothesis / exact change + flags / result numbers / reading / decision, the user's design decisions quoted, a
negatives table (tried → outcome → why), costs, open questions. Link it from the wiki log; the log entry stays
the summary. Pull the numbers from the result files, not from memory. Related: [[one-change-per-run-subtract-to-find-fault]],
[[research-method-rules]], [[transcript-is-the-notes]], [[retain-source-corpus-on-first-read]].
